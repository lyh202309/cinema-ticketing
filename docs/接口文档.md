# 电影院订票系统 · 接口文档

> 配套：《设计文档.md》（架构决策、表结构、Redis key 全在那边）
> 技术栈：Spring Boot 3 + MyBatis-Plus + Redis + RabbitMQ + LangChain4j(DeepSeek) + JDK17

---

## 0. 通用约定

### 0.1 统一返回

```json
{ "code": 1, "msg": "ok", "data": { } }
```

- `code=1` 成功；`code=0` 业务失败（`msg` 描述原因）；HTTP 403 = 越权/非法操作
- `data` 为 null 时省略或返回 null

### 0.2 鉴权

- 登录后后端发 `token`，前端请求头携带（`authorization`）
- 双拦截器：`RefreshTokenInterceptor` 校验 + 刷新 token、把用户塞进 ThreadLocal；`LoginInterceptor` 拦截需登录接口
- **所有操作型接口的 `userId` 一律从 ThreadLocal 取，绝不信任前端传的 userId**

### 0.3 时间格式

`yyyy-MM-dd HH:mm:ss`；`date` 参数格式 `yyyy-MM-dd`

### 0.4 两种"买票失败"的提示语义（用户感知层）

| 场景 | 返回 |
|---|---|
| 抢资格失败（名额满/被限流） | 提示"**当前人数过多，服务器繁忙，请稍后重试**" |
| 无资格却直接访问热门场次座位图/锁座 | **403 非法操作** |

> 设计原则：用户在整个正常流程中**感知不到"资格"机制的存在**。

## 1. 用户模块 `/user`

### 1.1 发送验证码
`POST /user/code?phone={phone}` — 免登录

- 生成 6 位验证码，存 `login:code:{phone}`，TTL 5 分钟（模拟发送，接口返回 ok）

### 1.2 登录
`POST /user/login` — 免登录

入参（两种登录方式二选一）：
```json
{ "phone": "13800138000", "code": "123456" }        // 验证码登录
{ "phone": "13800138000", "password": "xxx" }       // 密码登录
```

逻辑：
- 验证码登录：校验 code 与 Redis 一致 → 查用户，无则**自动注册**
- 密码登录：校验密码
- 生成 token（UUID）→ 用户信息存 `login:token:{token}`，TTL 30 分钟

出参：`data: { token, ... }`

### 1.3 登出
`POST /user/logout` — 需登录
- 删除 `login:token:{token}`

### 1.4 我的信息
`GET /user/me` — 需登录
- 返回 ThreadLocal 中当前用户（昵称/头像/手机号），无 DB 查询

## 2. 电影 / 影院 / 场次浏览（免登录）

> 详情接口缓存策略：**自实现布隆过滤器**拦截不存在的 id → `cache:xxx:{id}` 缓存，未命中查 DB，空结果写**空值缓存**（防穿透），重建缓存用**互斥锁**（防击穿）。列表接口做列表缓存。

### 2.1 电影列表
`GET /movie?genre={}&page={}&size={}`
- `genre` 可选（按类型筛）；返回分页电影列表（含评分）

### 2.2 电影详情
`GET /movie/{id}`
- 布隆过滤：id 一定不存在 → 直接返回空，不打 DB
- 返回影片信息（片名/类型/时长/评分/海报/简介）

### 2.3 影院列表
`GET /cinema?region={}&page={}&size={}`
- `region` 可选（按区筛）；返回分页影院列表（含评分）

### 2.4 影院详情
`GET /cinema/{id}`
- 返回影院信息 + 影厅列表（名字、座位行列数）

### 2.5 场次查询（三个浏览路径合一）
`GET /session?movieId={}&cinemaId={}&date={}&page={}&size={}`

- 三参数**均可选、可组合**：按电影查 / 按影院查 / 按日期查
- `date` 语义：**按 `start_time` 落在 `[date 00:00, date+1 00:00)`**（用户哪天去影院=开场那天）
- 返回分页场次列表（含影片、影院、影厅、票价、是否热门、开售时间）

### 2.6 场次详情
`GET /session/{id}`
- 返回场次完整信息（影片/影院/影厅/时间/票价/`is_hot`/`sale_start_time`/`sale_end_time`/座位总数）

## 3. 抢资格 / 选座 / 锁座（核心链路，均需登录）

### 3.1 抢资格
`POST /seckill/qualify/{sessionId}`

校验顺序：
1. 场次必须 `is_hot=1`
2. `sale_start_time ≤ now < sale_end_time`
3. **二级限流**：Guava 本地令牌桶（总 1000 QPS）→ Redis 滑动窗口（每用户 5s/3 次），超限快速拒绝
4. **Lua 原子脚本**（Redis 单线程保证并发唯一）：
   ```lua
   ZREMRANGEBYSCORE qualify:pool:{sid} -inf now        -- 清过期=名额自然回流
   if ZSCORE qualify:pool:{sid} {userId} then return 2  -- 已抢过
   if ZCARD qualify:pool:{sid} >= 3*座位数 then return 1 -- 名额满
   ZADD qualify:pool:{sid} (now+3min) {userId}
   return 0
   ```

出参 `data`：
| code | 语义 | 前端行为 |
|---|---|---|
| 0 | 抢到资格 | 跳转座位图页 |
| 1 | 名额满 | 提示"人数过多，服务器繁忙，请稍后重试" |
| 2 | 已抢过 | 提示"请勿重复操作" |

> 无独立"名额余量"查询接口——**不让用户感知资格限额存在**。

### 3.2 座位图
`GET /seckill/seatmap/{sessionId}`

- **热门场次**：校验该用户在 `qualify:pool:{sessionId}` 存在且未过期（`ZSCORE` 且 score>now），否则 **403 非法操作**
- **普通场次**：不校验，直接返回
- 组装：DB `tb_hall` 取 `rows×cols` + Redis `seats:session:{id}` → `int[rows][cols]`
- Redis 座位状态缺失 → 从 DB 重建：`tb_order_seat JOIN tb_order WHERE session_id=? AND status IN (0待支付,1已支付)`，再写回 Redis

出参：
```json
{ "rows": 10, "cols": 20, "seats": [[0,0,1,...], ...] }
// 0 可售 / 1 已锁 / 2 已售（Redis 内两态也够，此处可输出占/闲，由前端置灰）
```

### 3.3 锁座 + 下单（一次完成）
`POST /seckill/lock`

入参：
```json
{ "sessionId": 1001, "seats": [ { "row": 5, "col": 6 }, { "row": 5, "col": 7 } ] }
```

完整调用链：
1. **停售校验**：`now < sale_end_time`，否则返回"已截止售票"
2. **资格校验**：热门场次查 ZSet（无 → 403 非法操作）
3. **一人一单**：Redis 标记 `userOrder:{sessionId}:{userId}` 存在 → 返回"您已有订单"
4. **Lua 原子锁座**：检查所有座位可售（`0`）→ 全部置 `1`（已锁）；任一被占 → 返回失败
   ```
   失败 → 前端提示"座位已被选择"，重新加载座位图
   ```
5. **同步落库**（事务）：`INSERT tb_order(status=0待支付)` + 每座 `INSERT tb_order_seat`
   ```
   落库异常 → 补偿：Lua 释放已置位座位(1→0) → 返回失败
   ```
6. `SET userOrder:{sessionId}:{userId}`（一人一单标记）
7. 发延迟消息（RabbitMQ TTL 5min，带 orderId）→ 超时检查用

出参：
```json
{ "orderId": 12345, "expireSeconds": 300 }
```

## 4. 订单 `/order`（均需登录）

> 所有状态变更的乐观锁 UPDATE **都带 `user_id` + 原状态双条件**（防越权 + 防状态竞态）：
> `UPDATE tb_order SET status=? ... WHERE id=? AND user_id=? AND status=?`

### 4.1 我的订单
`GET /order/my?status={}&page={}&size={}`
- 按当前用户查；`status` 可选（0待支付/1已支付/2已取消/3已退款）

### 4.2 订单详情
`GET /order/{orderId}`
- 校验归属（只能看自己的订单）；返回订单 + 座位列表

### 4.3 支付（模拟）
`POST /order/{orderId}/pay`

```sql
UPDATE tb_order SET status=1已支付, pay_time=now
  WHERE id={orderId} AND user_id={当前用户} AND status=0待支付
```
- 0 行 → 返回"订单已失效"（可能已被取消/不属于你）
- 成功 → `ZREM qualify:pool:{sessionId} {userId}`（资格腾名额）→ 返回成功

> 模拟支付：点击即成功，不接第三方。

### 4.4 主动取消
`POST /order/{orderId}/cancel`

```sql
UPDATE tb_order SET status=2已取消, cancel_time=now
  WHERE id={orderId} AND user_id={当前用户} AND status=0待支付
```
- 成功 → Lua 释放该订单座位(1→0) + `DEL userOrder:{sessionId}:{userId}`
- 返回 → 前端回选座页。资格若仍在 3min 内可重新锁座下单；资格已过期则需重新抢资格

### 4.5 退票
`POST /order/{orderId}/refund`

```sql
UPDATE tb_order SET status=3已退款, refund_time=now
  WHERE id={orderId} AND user_id={当前用户} AND status=1已支付
```
- 成功 → Lua 释放该订单座位(2→0) → 返回成功
- **整单退**（该订单所有座位一起释放）

## 5. AI 对话助手 `/chat`（均需登录）

> 方案 A：只读咨询 + 预留半代办。A 阶段只注册只读工具；B 阶段解锁锁座/下单卡片。

### 5.1 会话列表
`GET /chat/conversations`
- 当前用户全部会话，按 `update_time` 倒序；返回 `[{id, title, updateTime}]`

### 5.2 新建会话
`POST /chat/conversations`
- 创建空会话（标题首条消息后生成），返回 `{id}`

### 5.3 历史消息
`GET /chat/conversations/{id}/messages`
- 校验归属；返回该会话全部消息（role/content/time），用于恢复对话上下文

### 5.4 发送消息（SSE 流式）
`POST /chat/conversations/{id}/chat`
```json
{ "message": "今晚有什么电影？" }
```
- 响应为 **SSE 流**（打字机效果），逐段返回 AI 回答
- 内部：组上下文（Redis 活跃缓存 30min + DB 历史）→ LangChain4j Function Calling → 调只读工具 → 流式生成 → **消息落 DB 永久存档**（conversation + message）

**工具清单（只读）**：
| 工具 | 作用 | 返回给 LLM |
|---|---|---|
| `searchSessions(movieId, cinemaId, date)` | 查场次 | 场次列表摘要 |
| `querySeatMap(sessionId)` | 查座位图 | 排布(rows×cols) + 座位状态串，LLM 自组织"摘要 + ASCII 座位图" |
| `queryMyOrders(status?)` | 查当前用户订单 | 订单列表 |

> 只读边界实现：A 阶段**不把操作类工具注册进 `AiServices.tools()`**，LLM 无法调用。
> B 阶段预留：`lockSeats` / `createOrder` / `refundOrder` 卡片接口。

### 5.5 删除会话
`DELETE /chat/conversations/{id}`
- 校验归属；删除会话 + 其全部消息

## 附录 A · Redis Key 规范

| Key | 类型 | 用途 | TTL |
|---|---|---|---|
| `login:code:{phone}` | string | 验证码 | 5min |
| `login:token:{token}` | string | 登录用户信息 | 30min |
| `cache:movie:{id}` / `cache:cinema:{id}` / `cache:session:{id}` | string | 详情缓存 | 30min+随机 |
| `seats:session:{sessionId}` | bitmap/hash | 场次座位占用状态 | 持久(可重建) |
| `qualify:pool:{sessionId}` | **ZSet** | 资格池：member=userId, score=到期 | — |
| `lock:seat:{sessionId}:{seatNo}` | string | 座位锁归属 key（幽灵锁 TTL 兜底） | 5min |
| `userOrder:{sessionId}:{userId}` | string | 一人一单标记 | 随订单 |
| `chat:ctx:{conversationId}` | string | AI 活跃会话上下文 | 30min |
| `rate:user:{userId}:qualify` | ZSet | 二级限流滑动窗口 | 窗口长度 |
